## **1. 목적 (Purpose)**

본 정책은 내부 작업 문서를 **일관된 유형(Type) 체계로 관리**하여,

- 문서의 목적과 역할을 명확히 하고
- 문서 작성 방식의 편차를 줄이며
- 장기적으로 재사용·자동화·공유가 가능한 구조를 확보하는 것을 목적으로 한다.

본 정책에 정의되지 않은 문서 유형은 **원칙적으로 생성하지 않는다.**

---

## **2. 문서 유형 체계 (Document Type System)**

모든 작업 문서는 아래 **7개 유형(Type ID)** 중 하나에 반드시 속해야 한다.

| **Type ID** | **유형명** | **목적** |
| --- | --- | --- |
| **T1** | Overview / Summary | 작업 전체 요약, 컨트롤 타워 |
| **T2** | Background & Context | 배경, 문제 정의 |
| **T3** | Plan / Design | 기획·설계 기준 |
| **T4** | Specification | 데이터/API/필드 명세 |
| **T5** | Policy / Rule | 운영 정책, 문구, 기준 |
| **T6** | Execution / Log | 작업 로그, 트러블 |
| **T7** | Validation / Result | 테스트, 검증, 결과 |

---

## **3. 문서 유형 사용 원칙**

### **3.1 단일 유형 원칙**

- 하나의 문서는 **반드시 하나의 Type ID**만 가진다.
- 하나의 문서에 **서로 다른 유형의 목적을 혼합하지 않는다.**

> 예: 설계(T3) + 트러블(T6)을 하나의 문서에 작성 ❌
> 

> → 각각 분리하여 작성 ⭕
> 

---

### **3.2 목적 우선 원칙**

- 문서의 Type은 **내용이 아니라 “작성 목적” 기준**으로 결정한다.
- 동일한 내용이라도 목적이 다르면 **다른 Type 문서로 분리**한다.

---

### **3.3 유형 확장 제한 원칙**

- 새로운 문서 유형 추가는 **원칙적으로 금지**한다.
- 예외적으로 필요할 경우,
    - 기존 Type으로 흡수 가능한지 먼저 검토
    - 팀 합의 후 별도 정책 개정으로 진행

---

## **4. 문서 유형별 정의 및 작성 기준**

---

### **T1 – Overview / Summary**

**정의**

작업 전체를 한눈에 파악할 수 있는 **최상위 요약 문서**

**사용 시점**

- 하루 작업 종료 시
- 작업 단위 마무리 시
- 공유/보고용 문서 필요 시

**포함해야 할 요소**

- 작업 목적
- 오늘 한 일 요약
- 주요 결정 사항
- 미해결 항목
- 다음 액션

---

### **T2 – Background & Context**

**정의**

문제를 왜 다루게 되었는지 설명하는 **맥락 정리 문서**

**사용 시점**

- 작업 착수 전
- 개선 요청 정리 시

**포함해야 할 요소**

- 현재 문제 상황
- 문제 발생 원인
- 해결하지 않을 경우의 리스크

---

### **T3 – Plan / Design**

**정의**

무엇을, 어떻게 만들 것인지 정의하는 **기획·설계 문서**

**사용 시점**

- 개발 전
- 작업 범위 확정 시

**포함해야 할 요소**

- 목표
- 포함 / 제외 범위
- 사용자 시나리오
- 설계 방향
- 결정 포인트

---

### **T4 – Specification**

**정의**

시스템 구현을 위한 **구체적 명세 문서**

**사용 시점**

- 개발 중
- API / 데이터 / 필드 정의 시

**포함해야 할 요소**

- 필드 / API / 이벤트 정의
- 데이터 구조
- 예시(Request/Response)
- 제약 사항

---

### **T5 – Policy / Rule**

**정의**

운영 기준과 판단 규칙을 명확히 하는 **정책 문서**

**사용 시점**

- 운영 기준 수립 시
- 문구·계약·판단 기준 정리 시

**포함해야 할 요소**

- 적용 대상
- 운영 기준
- 명시 문구
- 예외 처리

---

### **T6 – Execution / Log**

**정의**

작업 중 발생한 사실과 기록을 남기는 **실행 로그 문서**

**사용 시점**

- 작업 진행 중
- 이슈 발생 시

**포함해야 할 요소**

- 발생한 이슈
- 임시 해결책
- 원인 추정
- 후속 조치

---

### **T7 – Validation / Result**

**정의**

작업 결과를 검증하고 판단하기 위한 **결과 문서**

**사용 시점**

- 기능 완료 후
- 릴리즈 전/후

**포함해야 할 요소**

- 검증 시나리오
- 실행 결과
- 정상 / 비정상 케이스
- 운영 관점 판단

---

## **5. 문서 메타데이터 규칙 (권장)**

모든 문서는 상단에 아래 메타데이터를 포함한다.

```
Type: T4 – Specification
Owner: gicheol
Status: Draft | In Progress | Done
Last Updated: YYYY-MM-DD
```

---

## **6. 정책 준수 가이드**

- 문서를 새로 만들 때는 **반드시 Type을 먼저 결정**
- “이 문서가 무슨 역할인지 설명이 안 되면” → Type이 잘못된 것
- 문서가 길어질수록 **분리 우선**

---

## **7. 정책 개정**

- 본 정책은 **실제 운영 중 발견되는 문제를 기준으로만 개정**
- 개정 시 반드시
    - 개정 사유
    - 변경 내용
    - 적용 시점 기록

---

## **8. 결론**

본 문서 유형 정책은 **문서를 줄이기 위한 정책이 아니라, 일을 빠르게 하기 위한 정책**이다.

문서가 늘어나더라도 **역할이 명확하면 관리 비용은 증가하지 않는다.**
